# Noema v0.23.0

This release adds optional decision-assisted retrieval using a local or hosted TypeSafe-compatible evaluator, plus conditional preference-revision support for safer context reuse across agent sessions.

## Changes

- Optional `typesafe_ai` evaluation can filter and score retrieval candidates before they are returned to an agent. When evaluation is disabled, unavailable, or fails closed, native retrieval results are preserved.
- Provider selection supports `auto`, `local`, and `hosted`. Local mode never auto-falls back to hosted credentials.
- Retrieval evaluation attempts are recorded under the provider-independent `decision_retrieval` operation name. Historical `jev_retrieval` rows are migrated in place.
- Trace-body caching and conditional preference-revision protocol reduce repeated preference reloads when a client already holds a matching revision.
- Hermes plugin helpers support preference-context lifecycle checks for revision reuse.
- CLI surface includes `noema typesafe status|metrics|probe|gate|pair` for activation inspection and advisory evaluation.
- Docs cover decision-assisted retrieval, native TypeSafe evaluation, and preference revisions.

## Upgrade

```sh
brew update
brew upgrade noema
```

Restart Noema servers and stdio MCP clients after upgrading. Existing Cortex data remains compatible. Builds that previously recorded `jev_retrieval` operation rows migrate those rows to `decision_retrieval` automatically.

Decision-assisted retrieval stays off unless `typesafe_ai` is configured and activated. No hosted credential is required for local-only operation.
