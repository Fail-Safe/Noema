# Noema v0.22.3

This patch release adds a non-breaking `noema:{id}` citation form for chat and agent paste recognition, and makes MCP tag/lineage inputs accept JSON string arrays as well as comma-separated strings while keeping Obsidian-compatible YAML lists on disk.

## Changes

- Tool and CLI inputs that take a trace ID accept `noema:{id}` and `noe://trace/{id}`, normalize to the bare `YYYYMMDD-slug` identity, and leave on-disk IDs unchanged.
- `get_trace` responses include a `citation` field (`noema:{id}`) while JSON `id` remains the bare ID.
- MCP inputs for `tags`, `derived_from`, and related list fields accept a JSON string array or a comma/semicolon-separated string. Stringified JSON arrays are rejected.
- Tags and lineage continue to persist as YAML lists for Obsidian Properties compatibility.
- Agent instructions and docs describe the citation scheme; see [Trace citations](../trace-citations.md).

## Upgrade

```sh
brew update
brew upgrade noema
```

Restart Noema servers and stdio MCP clients after upgrading. No data migration is required. Existing clients that send comma-separated tag strings keep working.
