# Noema v0.22.0

This stable release adds opt-in local database storage for synced cortexes, explicit storage diagnostics and compaction, focused MCP endpoints, embedding size recovery, and more reliable service startup.

## Storage and MCP

- `noema cortex storage`: inspect database size, WAL size, reusable pages, and available space; safely migrate between `db/` and `db.nosync/` with a required full backup and interrupted-migration recovery.
- `noema cortex compact`: explicitly reclaim unused database space with a required backup, integrity checks, and space checks. No automatic periodic VACUUM is enabled.
- Focused MCP endpoints: `/mcp/agent` (24 tools), `/mcp/maintainer` (30), `/mcp/curator` (26), and `/mcp/federation` (3). `/mcp` continues to expose all 35 tools.
- Profile-aware instructions describe sibling endpoints and their additional capabilities.

## MCP behavior and storage locking

- Retrieval and diagnostic tools advertise read-only intent to MCP clients. Normal retrieval still records usage signals used by Noema's memory model.
- Storage-aware clients hold a local runtime lock outside the cortex, plus a compatibility lock for earlier storage-aware builds. Replacing a synced compatibility lock does not bypass the runtime lock.
- Prereleases do not update the stable Homebrew formula or cask.

## Storage fixes

- Reopening a cortex with unavailable trace files no longer repeatedly rebuilds an otherwise current search index.
- Storage migration preserves existing Unix configuration permissions, including recovery after interruption, along with comments and unknown YAML fields.
- Compaction closes SQLite before its required archive is copied, and backups omit the transient storage lock file, avoiding Windows locked-file read failures.

## Embedding and startup reliability

- Refuse embedding and tokenization redirects so trace-derived input stays on the configured provider endpoint. Configure the final provider URL directly.
- Recover from recognized embedding context and batch-size limits by isolating oversized inputs and preserving successful neighboring embeddings.
- Support optional exact token budgets through a compatible tokenizer on the embedding server. Trimming affects derived embedding input only; stored traces remain intact.
- Track truncated vectors, preparation metadata, and retry cooldowns. Apply cooldown before backfill limits so an oversized trace does not block later work; report incomplete coverage clearly.
- Rebuild stale embeddings when preparation settings or trace titles change. Migration 022 preserves existing vectors while adding local derived-index metadata.
- Wait up to 30 seconds for configured static listener addresses to become available during startup. Keep ready listeners bound and fail port conflicts and permission errors immediately.

## Upgrade notes

- Restart all Noema clients after upgrading so they acquire the storage runtime lock. Use a consistent local runtime directory across clients.
- Storage migration and compaction require an offline maintenance window. Stop servers, watchers, older clients, and direct SQLite tools, and prevent restarts until maintenance finishes. Locks coordinate participating Noema clients; arbitrary SQLite writers must remain stopped.
- `.nosync` keeps the database local while Markdown traces can continue syncing. Another device needs a complete backup restore; retain backups outside the synced folder.
- Existing embeddings without preparation metadata become stale for backfill. Token budgets are opt-in and require compatible server tokenization. Trimming changes derived embedding input only; stored trace content and federation format remain unchanged.

## Qualification

The GA source additionally refuses provider redirects, with embedding and tokenizer regression tests. RC2 completed a continuous 24-hour signed two-node federation and embedding soak with 97 successful samples and zero failures. Certificate-verified MCP, database integrity, current embedding coverage, and event deduplication passed. Release qualification also covered six platform builds, storage/recovery tests, plugin checks, and mixed-version federation.
