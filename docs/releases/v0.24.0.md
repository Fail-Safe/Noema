# Noema v0.24.0

This minor release adds on-demand Tag Review and version-aware OpenCode V1/V2
integration. It does not alter the published continuity evidence or add
dependency updates.

## Tag Review: suggestions, not automatic changes

Open `noema tui` and press **T**, or use `noema tags review`.

- Queue local hygiene suggestions or explicitly request bounded model analysis.
  Model output creates proposals only; applying or undoing tags requires approval
  of the exact preview. Reject, defer, resume, and edit proposals independently.
- Select **Shared** consolidation-model settings or a **Separate** review model.
  Saving settings does not make a model call. Consent pins the chosen destination
  for that analysis; subsequent changes apply to later runs.
- Protect behavioral/routing selectors and source-locked foreign traces. Stale
  evidence prevents apply/undo, and missing proposals cancel pending UI actions.
- Persist queue decisions locally. Approved tag updates, their indexes, and their
  normal federation events use the existing crash-recovery path, including under
  standard durability. Review proposals and decisions are not federated.

The full and maintainer MCP profiles add `tag_review_queue`, `tag_review_analyze`,
and `tag_review_decide`. Other profiles are unchanged. The confirmation boolean
is an agent approval contract, not independent human authentication.

Model analysis is opt-in and bounded: up to 40 trace excerpts per window, up to
10 per request, explicit request/time/response limits, and partial-progress
reporting. Truncated output is split and retried within those limits; completed
proposals survive later failures. There is no scheduler or automatic application.
Use a trusted endpoint; redirects are disabled and credentialed requests require
HTTPS. See [Tag Review](https://github.com/Fail-Safe/Noema/blob/v0.24.0/docs/tag-review.md).

## OpenCode adapters and capture

The installer selects V1 or V2 from the actual executable version, with a target
configuration fallback when the executable cannot be probed. Unsupported major
versions are refused before writes. V2 uses `mcp.servers` and its context-hook
bootstrap; V1 retains the legacy adapter.

V2 bootstrap is supplied once to ordinary model requests, omitted from completed
compaction-summary generation, and supplied again once after compaction. The
legacy V1 system hook still supplies bootstrap to summary requests; this existing
limitation is not presented as fixed.

Ephemeral capture disables ordinary Noema and selects only the two capture tools,
without rewriting persistent configuration. A customized
`plugins/noema-session-bootstrap/` directory is treated as an ownership conflict,
including under `--force`, rather than installing a duplicate flat plugin or
removing the customization. Configuration-file replacement is atomic; the
configuration and plugin files are not one cross-file filesystem transaction.

## Upgrade and local queue storage

Back up the Cortex directory, including `cortex.md`, Markdown traces, and
`db/noema.db`, before upgrading. Stop existing Noema processes and restart all
servers/stdio clients with the upgraded executable before using Tag Review.

Migration **025** adds the local review queue and purge-cleanup triggers when a
Cortex is opened. Existing trace Markdown is not rewritten by that migration.
Review decisions/excerpts are database state: rebuilding only from Markdown
cannot recover the queue or decision history. This release does not provide a
reverse migration or a universal downgrade guarantee.

```sh
brew update
brew upgrade noema
```

Alternatively, download the matching platform archive and verify its checksum
against `checksums.txt`, or build from the v0.24.0 source tag. Publishing the release
does not itself upgrade or restart resident services.

## Verification scope

Qualification uses Rust 1.88, full tests and strict linting, reviewed mutation and
recovery regressions, actual CLI/MCP/TUI interactions, and disposable data.
Semantic request handling is exercised with deterministic loopback providers,
not a claim about the quality of any real model's taxonomy suggestions.

Fresh OpenCode runtime probes use installed **1.18.31** and the checksum-verified
official **2.3.0** executable. V2 proof includes completed compaction, bootstrap
counts, actual capture connection/catalog adoption, and persistent-byte
preservation; it is not a live-model mutating capture benchmark. Customized
bootstrap-directory refusal is exercised through the actual CLI. Historical
2.1.4 evidence is not requalified. Live user configuration is not modified.
