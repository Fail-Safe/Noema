# Noema v0.22.1

This patch release fixes trace creation with non-ASCII titles ([#203](https://github.com/Fail-Safe/Noema/issues/203)) and federation usage sync after a local trace purge ([#201](https://github.com/Fail-Safe/Noema/issues/201)).

## Fixes

- Cyrillic, CJK, and other Unicode titles no longer generate IDs rejected by trace validation. This applies to MCP `create_trace`, `create_traces`, and other creation paths using the shared ID generator.
- Generated slugs use lowercase ASCII letters, digits, and hyphens. Other characters act as separators; when no slug remains, a deterministic short SHA-256-derived suffix supplies a valid ID.
- Original titles and bodies remain unchanged in Markdown and the database. Existing traces are not renamed, and the ID validator and 100-character slug limit are unchanged.
- Federation usage merges skip valid remote usage rows whose trace no longer exists locally, rather than aborting the whole batch with a foreign-key error. Usage for retained traces still merges monotonically, and the usage cursor advances past skipped rows. Invalid usage rows still fail validation.

## Acknowledgments

Thanks to [@prismatic7](https://github.com/prismatic7) for reporting the Unicode trace-ID problem in [#203](https://github.com/Fail-Safe/Noema/issues/203) and contributing the proposed fix in [#202](https://github.com/Fail-Safe/Noema/pull/202). The release fix incorporates a separate deterministic ASCII-ID implementation; the contribution helped identify and resolve the issue.

## Upgrade

```sh
brew update
brew upgrade noema
```

Restart Noema servers and stdio MCP clients after upgrading. No data migration is required for these fixes.

## Qualification

- Regression coverage exercises Unicode MCP creation, distinct deterministic fallback IDs, ASCII slug truncation, and generated-ID validity across arbitrary Unicode titles.
- Formatting, strict Clippy, the full Rust suite, and repository benchmark-mechanics tests passed locally with serialized test execution. The default parallel macOS run encountered mutation-lock contention in three existing tests.
- The optimized macOS ARM64 binary passed real stdio MCP creation and retrieval checks for Cyrillic, CJK, emoji, mixed-script, punctuation-only, and long titles, plus batch creation and stable duplicate IDs.
- A real two-cortex HTTP federation check exercised local purge, mixed absent/present usage rows, cursor advancement, stable repeat sync, and clean foreign keys. Regression coverage also verifies that invalid rows remain rejected.
