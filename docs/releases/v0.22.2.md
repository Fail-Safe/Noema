# Noema v0.22.2

This patch release updates the TLS dependency to address [GHSA-2mjx-qc3c-rqvc](https://github.com/advisories/GHSA-2mjx-qc3c-rqvc), hardens embedding credential transport, and includes six reviewed dependency updates.

## Security

- Updated `rustls` from 0.23.43 to 0.23.45. The advisory affects TLS 1.3 handshake messages accepted across encryption-level boundaries; the patched version rejects those invalid messages. The locked update applies to both the HTTPS server and HTTP/federation clients.
- Embedding and tokenization now require HTTPS whenever a nonempty API key or URL credentials are configured, including localhost and loopback endpoints. Credentialed clients also enforce HTTPS at request time, and redirects remain disabled.
- Rejected credentialed endpoints are not included in error messages. Embedding status/backfill no longer print configured endpoint URLs, and request/response errors omit request URLs so credentials and query values do not leak into diagnostics. Credential-free HTTP remains supported.

## Upgrade

```sh
brew update
brew upgrade noema
```

Restart Noema servers and stdio MCP clients after upgrading. No data migration is required.

**Authenticated local embedding providers using HTTP must enable TLS or remove their credentials before upgrading.** This applies to bearer API keys and credentials embedded in endpoint URLs. Missing or empty API-key environment variables do not enable bearer authentication; credential-free HTTP providers keep working.

## Qualification

- Formatting, strict Clippy, and the complete Rust suite passed on Rust 1.88 with serialized local test execution, followed by an optimized macOS ARM64 build.
- The actual optimized binary passed stdio handshakes, legacy and modern HTTP discovery/calls across all five role endpoints, session isolation, role denial, duplicate routing-header rejection, Origin restrictions, and the real federation client path.
- Bidirectional signed HTTPS federation between the published v0.22.1 binary and the new binary passed, including custom-CA trust, missing/wrong-key refusal, authentication recovery, and keyed plaintext refusal.
- Actual CLI embedding backfill rejected HTTP bearer and URL credentials before contacting the provider, without exposing credentials. Credential-free HTTP embedding and both default/custom tokenization paths succeeded without an Authorization header.
- Before/after CLI checks reproduced credential-bearing endpoint output in v0.22.1 and verified its removal in the new binary. Regression coverage also verifies credential-safe embedding/tokenizer request failures without hiding the failure itself.
- The migrated historical semantic-search harness passed using v0.22.1 and v0.22.2 as the two comparison binaries; this is release-to-release verification, not a new Go-oracle qualification.
- Obsidian tests, build, and TypeScript checking passed. Hermes tests, release metadata tests, brand-asset script tests, and continuity benchmark-mechanics tests passed.
